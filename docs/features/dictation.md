# Dictation (fn+⌃)

Screen-aware dictation: hold fn+⌃, words spelled from the screen, tidied and pasted. Part of the project rules (see `CLAUDE.md`).

**Screen-aware dictation, fn+⌃ (user's request, 2026-10-20).** Hold fn+⌃ (`ChordDetector.dictate`; `Modifiers.function` from `.function`), speak, let go: the words go into the focused field (`DictationController`, `Dictation` in Core, tested). At the press: the microphone (`AskCoordinator.startDictation`, the same checks as a card's voice panel, `voiceUnavailable`), the companion Shamrock (`OverlayModel.isDictating` → `.action`) with the listening bars following the voice — not the action pulse — and the focused field read off the main thread (`AXInspector.dictationTarget`: window title, up to 80 control names, role/subrole, editable, the text before the caret; password fields give no text). No screenshot, never peeled (⌃⌥ is ignored while dictating). At the release: Shamrock spin; Whisper transcribes with the screen's distinctive words plus the caret's last 160 characters as its prompt (`Dictation.hints`, ≤ 400 characters, ≤ 120 tokens, `Transcriber.transcribe(_:prompt:)`); the local model tidies it (`Prompt.dictationSystem`, text only, `{"text"}` schema, style from the app: casual chat apps, written mail/documents, code terminals/editors, else plain) within `Dictation.tidyLimit` (3 s + 1 s per 150 characters) — slow, malformed, or not the same words (much shorter/longer: it answered instead) → the raw words (`parseTidy`). A space is added when it would run into the previous word (`joined`). **ClickBait pastes it (user's call, the one place it types):** the clipboard is borrowed (text marked `org.nspasteboard.TransientType`), ⌘V posted with only ⌘, and the old clipboard put back 0.5 s later unless something changed it. Only copied, with the pill "transcribed · ⌘V to paste" (user's wording), when no editable field is focused, in a password field (`AXSecureTextField`), or when another app came to the front meanwhile (`Dictation.delivery`). Another key or modifier drops it. The log has lengths and timings only, never the words. Non-Apple keyboards usually send no fn: dictation needs a Mac keyboard. If the Globe key is set to Start Dictation or Emoji, check it doesn't fire too.

**Apple on-device speech (2026-10-21, idea from Sentient OS).** Settings → Speech recognition offers "Apple on-device (English, macOS 26+)" beside the Whisper models, only where `SpeechTranscriber.isAvailable` (`SpeechModel.offered`). `AppleSpeech` (macOS 26 `SpeechAnalyzer` + `SpeechTranscriber`, en_US, `.transcription` preset, finals only) takes the same 16 kHz samples as Whisper, converted to `bestAvailableAudioFormat`, and its text goes through `TranscriptCleaner`. Download installs Apple's asset (`AssetInventory`, user-started); choosing it unloads Whisper. No import (it's a system asset), and dictation's screen-word prompt only steers Whisper. Not yet tried end to end (needs the asset installed).

**Whisper Large Turbo, for other languages (2026-11-01, user's ask).** ClickBait already hears through Whisper (WhisperKit: Tiny, Base, Small English). Settings ▸ Speech recognition now also offers **Large Turbo (any language, ~630 MB)**: the spoken language is detected (`Transcriber.multilingual`, from a model folder without `.en`), not assumed English. Its tokenizer is Large v3's (`SpeechModelImport.tokenizerName`). Measured with `SpeechBenchTests` (opt-in, `TEST_RUNNER_CLICKBAIT_SPEECH_BENCH=1`; 12 sentences spoken by macOS voices): Small 4.8% word errors, 0.21 s a sentence; Turbo 4.8%, 0.44 s. So English stays on Small (the default for this Mac); Turbo is for speaking other languages.
